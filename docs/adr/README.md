# Architecture decisions

Each accepted decision records the constraint that drove it, the resulting
tradeoff, evidence and a condition for revisiting it.

| Decision | Context and options | Rationale and consequence | Evidence and revisit trigger |
| --- | --- | --- | --- |
| 001 · Local-first, loopback-only | Compare a local single-user service with a hosted API and model. | SQLite and local inference keep the library and evidence on the machine. Imports still depend on an external source. Users maintain the local runtimes and backups. | [Operations](../operations.md). Revisit if a concrete shared-access requirement exists. |
| 002 · SvelteKit and FastAPI | Compare a Python-rendered UI with a typed browser client using a local API. | Browser interactions and presentation evolve independently. One backend owns game logic. The packaged launcher serves a static build and API on one origin. | [HTTP contract](../api-contract.md). Revisit if browser routing or the API boundary creates measured friction. |
| 003 · SQLite and Alembic | Compare an embedded database with a separately managed database server. | A single local library can use transactional writes and file-backed snapshots without another process. Write concurrency is bounded by SQLite and job admission. | [Persistence](../PERSISTENCE.md) and [recovery evidence](../reliability/phase20-report.md). Revisit when lock contention is measured under the supported workload. |
| 004 · Stockfish and Python own chess evidence | Compare engine-backed facts with model-generated chess analysis. | Legality comes from python-chess, evaluations come from Stockfish, and aggregates come from Python. The model receives compact evidence for interpretation. Search quality depends on the engine profile. | [Acceptance criteria](../ACCEPTANCE.md). Revisit the budget when fixed-workload comparisons support a change. |
| 005 · Local Qwen 4B with guarded output | Compare deterministic-only explanations with a bounded local generation step. | Use the already installed quantized model and validate output before persisting it. The schema catches specific errors. Independent human review is required for quality claims. | [Model selection](../evaluation/model-selection.md). Revisit after a reviewed comparison using identical evidence and model settings recorded by digest. |
| 006 · One analysis profile and a history-aware cache | Compare a single budget with fast and deep passes across all games. | Cache compatible positions and reuse one engine process per run. Extra puzzle verification is a separate use case. Keep historical analysis at one budget while measuring search throughput and quality. | [Analysis runbook](../operations/analysis-runbook.md). Revisit when measured weak evaluations justify selective deeper searches. |
| 007 · Local workers and relational evidence | Compare durable SQLite jobs and exact evidence queries with distributed queues or semantic retrieval. | Claim and resume jobs with local worker ownership. The worker releases Stockfish before coaching to bound competing resource use. SQL can retrieve the needed games, move evidence and pattern references. | [Recovery evidence](../reliability/phase20-report.md). Revisit after concurrent benchmarks or a concrete retrieval requirement justify it. |
